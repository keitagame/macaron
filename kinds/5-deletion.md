# kind 5: 削除 (deletion)

- 保存: regular
- 現行API: `delete_post`、およびトグル型API(`like` `react` `repost` `follow` `bookmark` `sens_vote`)の「解除」側
- 関連機能: すべて

## 目的

自分のイベントを取り消す。リレーは対象を削除し、**同じ `id` の再投稿を拒否**する(墓標)。

## 構造

```json
{
  "kind": 5,
  "content": "誤爆のため",
  "tags": [["e", "<削除したいイベントid>"], ["e", "<別のid>"], ["k", "1"]]
}
```

| タグ | 意味 |
|---|---|
| `e` | 削除するイベントのid(複数可) |
| `a` | 削除する addressable イベント(`kind:pubkey:d`) |
| `k` | 対象の kind(任意。確認用) |

### kind 全消去

`e` も `a` も無く `k` だけの削除 `["k","7"]` は、**この削除より前に作られた**自分の kind 7 イベントをすべて削除する。現行 `noview`(閲覧履歴の全消去)に当たる。リレーは MAY 対応(`features` に `delete:bykind`)。

## リレーの検証

- 対象イベントの `pubkey` が削除イベントの `pubkey` と**一致するものだけ**削除する(他人のイベントは無視)。
- kind 5 自体を削除対象にしても無効(削除の取り消しはできない)。
- 対象が未到着でも `id` を墓標に記録し、後から届いたら保存しない。

## クライアントの扱い

- 削除済みの投稿は「ポストが見つかりません」として扱う。引用元が削除されたときは `{deleted: true}` 表示(現行 `quoteOf` と同じ)。
- 削除はリレー単位。**他のリレーに残っているコピー、他人が保存したコピーは消えない**(分散の性質)。UIでそう案内する。
- リアクション・リポスト・フォロー・ブックマークの解除に使う。関連する派生データ(通知・集計)はイベントから都度算出するので、現行の `unnotify()` のような後始末は不要。

## 拡張ポイント

- 「理由コード」を `content` の接頭辞(`spam:` など)で約束事にできる。
