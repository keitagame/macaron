# kind 30002: トレンド (trends)

- 保存: addressable(**リレー自身の鍵で署名**)
- 現行API: `trends`
- 関連機能: [trends](../features/trends.md)

## 目的

「いま話題の語・タグ」を、リレーが計算して**通常のイベントとして配る**。専用エンドポイントを増やさず、購読(`REQ`)の仕組みにそのまま乗せる。署名があるので、どのリレーが出した結果かが検証できる。

## 構造

```json
{
  "kind": 30002,
  "pubkey": "<リレーの公開鍵>",
  "created_at": 1730700000,
  "content": "[{\"tag\":\"#hello\",\"q\":\"#hello\",\"label\":\"トレンド\",\"count\":12},{\"tag\":\"広島\",\"q\":\"広島\",\"label\":\"話題\",\"count\":8}]",
  "tags": [["d", "main"], ["expiration", "1730700120"]]
}
```

| `content` の各項目 | 意味 | 現行 |
|---|---|---|
| `tag` | 表示する語 | `tag` |
| `q` | 押したときの検索語(`#…` なら ハッシュタグ検索) | `q` |
| `label` | 見出し(「トレンド」「急上昇」など) | `label` |
| `count` | 直近24時間のポスト数 | `count` |

- `d` = 集計範囲。`main` = 全体。将来 `jp` `en` などを足せる。

## リレーの検証

- 受け付けるのは `pubkey` が**リレー自身の鍵**のものだけ(他人が書いても `blocked:`)。

## クライアントの扱い

- `REQ {"kinds":[30002],"authors":["<リレーのpubkey>"],"#d":["main"]}` で1件取得。リレーの鍵は `GET /` の `pubkey`。
- 更新は購読していれば自動で届く。`expiration` を過ぎた値は使わない。
- 複数リレーのトレンドを並べる/合成するのはクライアントの自由。

## 計算(参考)

現行の `compute_trends()`: 直近8時間の語の勢い(半減期90分)と、過去7日間の平常頻度を比べ、ユーザー数・ポスト数で重み付けして上位5件。更新は60秒キャッシュ。**アルゴリズムはプロトコルの外**(リレーの実装の自由)。

## 拡張ポイント

- `content` の項目に `score` `sample`(代表投稿id)などを足せる。
