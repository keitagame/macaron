# kind 7: 閲覧記録 (view)

- 保存: regular(リレーは `(pubkey, e)` ごとに最新1件だけ保持してよい)
- 現行API: `view_seen`, `thread` の閲覧記録, `noview`
- 関連機能: [view-history](../features/view-history.md) / [recommendation-feed](../features/recommendation-feed.md) / [setting](30001-setting.md)

## 目的

「この人がこの投稿を見た」という記録。投稿者への「閲覧者一覧」と、おすすめ順の「見たことがある投稿は下げる」に使う。**任意機能**。

## 構造

```json
{ "kind": 7, "content": "", "tags": [["e", "<投稿id>"], ["p", "<投稿の作者>"]] }
```

- 1イベント = 1投稿。まとめて送るときは `POST /msg` のバッチを使う([07-transport-sse](../core/07-transport-sse.md))。
- 自分の投稿は記録しない(現行と同じ)。

## リレーの検証

- 読み出しに認証が必要: `kinds:[7]` の `REQ` は認証済みの接続だけ(`auth_required_kinds`)。現行の「閲覧者一覧はログイン中の人にだけ見せる」に対応。
- 保持: `(pubkey, e)` が同じなら新しいもので置き換え(現行 `INSERT OR REPLACE`)。古い記録を `expiration` で自動削除してもよい。
- `max_views_per_minute` 程度の上限(現行 60回/分・1回50件)。

## クライアントの扱い

- 記録しない選択(現行の「閲覧を記録しない」)= **単にイベントを送らない**。設定は [kind 30001](30001-setting.md) の `no_view` に保存して端末間で揃える。切り替えたら過去分を消す: [kind 5](5-deletion.md) の `["k","7"]`。
- 閲覧者一覧 = `REQ {"kinds":[7],"#e":["<id>"],"limit":200}` → `pubkey` をプロフィールに解決。
- 画面に表示されただけ(開かなくても)で記録する挙動は、クライアントの実装方針で、プロトコルは関知しない。

## プライバシー

閲覧は**認証済みの人にだけ**見える設計だが、リレー運営者には見える。気になる人は記録を送らない選択ができる(分散では「サーバーに嘘をつかない」=「送らない」)。

## 拡張ポイント

- 滞在時間などを `["dur","<秒>"]` タグで足せる。
