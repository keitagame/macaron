# kind 30000: カスタム絵文字 (emoji)

- 保存: addressable(`pubkey` + `d` = 絵文字名)
- 現行API: `emoji_add`, `emoji_delete`, `emoji_list`
- 関連機能: [custom-emoji](../features/custom-emoji.md)

## 目的

「自分が作った絵文字 `:name:`」を公開する。ピッカー(一覧)のためのイベントで、**投稿やリアクションの表示には必須ではない**(それらは `emoji` タグで自己完結する)。

## 構造

```json
{
  "kind": 30000,
  "content": "",
  "tags": [
    ["d", "party"],
    ["url", "https://cdn.example.com/e/party.webp"]
  ]
}
```

- `d` = 絵文字名。`^[a-z0-9_]{2,32}$`(現行と同じ)。
- `url` = 画像のURL(静止画は 128px 以内、アニメGIFは 256px・512KB 以内が現行の制限。メディアサーバーが検査)。

## 名前の衝突

現行は全ユーザーで名前が一意だったが、分散では**作者ごとに名前空間が違う**。同名の別の絵文字がありうるので:

- 投稿・リアクションは必ず自分の `["emoji", name, url]` タグを持つ → 受け手は**タグの URL を使う**(作者の定義を参照しない)。
- 同名で別URLが混ざる場合は、イベントごとのタグが勝つ。

## リレーの検証

- `d` が名前の正規表現に合う。`url` が `https:`。
- 1人あたり `max_emoji_per_user`(現行 50)。超えたら `restricted:`。

## クライアントの扱い

- ピッカー = 自分の絵文字 `{"kinds":[30000],"authors":["<me>"]}` + フォロー中の人の絵文字。
- 削除 = [kind 5](5-deletion.md) の `a` タグ(`30000:<pubkey>:<name>`)。**過去の投稿・リアクションの `emoji` タグはそのまま残る**ので表示は変わらない(現行の「削除したらリアクションも消す」は再現しない。画像URLが消えたら代替テキスト `:name:` で表示する)。

## 拡張ポイント

- 絵文字セット(複数まとめ)は `["set","<名前>"]` タグ。
- アニメ有無・ライセンスは `["m","image/gif"]` `["license",…]` を足す。
