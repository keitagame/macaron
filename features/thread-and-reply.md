# 機能: スレッドと返信

- 使う kind: [1](../kinds/1-post.md)
- 現行API: `thread`、`post` の `parent_id`

## 返信を書く

[kind 1](../kinds/1-post.md) に `["e", <親id>]` と `["p", <親の作者>]` を付ける。親の `e` は**直接の親だけ**(現行の `parent_id` と同じ。「ルート」は持たない)。

```json
{ "kind": 1, "content": "いいね!", "tags": [["e","<親id>","wss://relay.example.com"],["p","<親の作者>"]] }
```

## スレッドを開く

```
REQ "t" [
  {"ids":["<id>"]},                              ← 本体
  {"kinds":[1],"#e":["<id>"],"limit":200}        ← 直接の返信(新しい順で届く→古い順に並べ替え)
]
```

- 返信の返信は、返信の `id` で同じ検索を繰り返す(クリックしたとき)。
- 親があれば「返信元のポストを見る」リンク(`e` タグの先頭値)。

## 件数

`COUNT {kinds:[1],"#e":[ids…],group:["e"]}`(1ページ分を1回で)。→ [counts](counts.md)

## 削除済みの親

親が見つからなくても返信は表示する。「返信元は削除されたか取得できません」を出す。

## プロフィールの「返信」タブ

`{"kinds":[1],"authors":["<x>"],"has":["e"],"limit":100}`(現行 `tab=replies`)。「ポスト」タブは `without:["e"]`。

## 通知

親の作者は `p` タグで通知される([notifications](notifications.md))。同じ作者へのスレッド全員通知はしない(現行どおり)。

## 拡張ポイント

- 深いスレッドを一括取得したいなら、`e` に `"root"` マーカーを足す(`["e", id, hint, "root"]`)。旧クライアントは3番目までしか見ないので壊れない。
