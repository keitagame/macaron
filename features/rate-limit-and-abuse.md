# 機能: レート制限・スパム対策

- 使う: リレーのポリシー([08-relay](../core/08-relay.md))、`OK`/`CLOSED` の接頭辞
- 現行: `throttle()` / `throttle_check()` / `throttle_hit()`(`throttle` 表、キー別・時間窓別)

## 考え方

分散では**誰でも鍵を無限に作れる**ので、アカウント単位の制限だけでは足りない。リレーは**自分の運営方針として**制限してよい(プロトコルの外)。ただし**拒否は黙って捨てず、理由を返す**。

## 制限の単位

| キー | 例 |
|---|---|
| `pubkey` | 投稿 30回/分、いいね・リアクション・リポスト 120回/分、フォロー 60回/分、DM 60回/分 |
| `IP` | 新しい pubkey の初回投稿 5回/時(現行 `su:` の置き換え)、ログイン系は不要 |
| `pubkey × kind` | 閲覧記録 60回/分、フラグ 60回/時 |
| 接続 | 購読数、`REQ` の頻度、COUNT の頻度 |

超過時: `["OK", id, false, "rate-limited: slow down (60/min)"]`。クライアントは待って再試行するかUIで案内。

## 現行の数値を `GET /` に出す

```json
"limits": { "rate": { "1": "30/60", "3": "120/60", "8": "60/60", "4": "60/60", "7": "60/60", "6": "60/3600" } }
```
(kind → 回数/秒)

## 追加の対策(リレーが選ぶ)

| 方法 | 内容 |
|---|---|
| 新規 pubkey の制限 | 初出から24時間は投稿頻度を絞る・フラグ無効(`restricted:`) |
| **PoW**(計算コスト) | 投稿に `["pow", "<nonce>"]` を付け、`id` の先頭ビットが0のn個以上を要求。botの量産を抑える。`policy.pow` で要求ビット数を公開。`blocked: pow 16 bits required` |
| 登録制 | ハンドル取得([handle](handle.md))や投稿を、招待・承認・有料の pubkey に限る |
| 許可リスト・禁止リスト | pubkey・kind・語・URLドメイン |
| 本文の検査 | 現行 `clean_text()` 相当(制御文字・長さ) |
| フラグ・通報 | [kind 6](../kinds/6-flag.md) を運営の判断材料に |

## クライアントの扱い

- `rate-limited:` `restricted:` `blocked:` を**そのまま利用者に見せる**。
- 送信キューを持って再送(指数バックオフ)。同じ署名済みイベントは再送してよい(`id` が同じなので `duplicate:` で無害)。

## DoS対策(リレー)

- イベントサイズ・タグ数・フィルタ数・`limit`・`authors` の上限をポリシーで持つ。
- `REQ` / `COUNT` は重いのでキャッシュ・タイムアウト(クエリ実行時間の上限)を設ける。
- SSE の接続数上限(特に共有ホスティングのPHP)を決め、超えたら 503 とポーリングへの切り替えを案内。
