# 機能: おすすめタイムライン

- 使う: 拡張フィルタ `feed: "rec"` / kind 1・2・3・8・7
- 現行API: `timeline` の `scope=rec`(`rec_rank()`、`asof` と `offset` で順位を固定してページ送り)

## 考え方

「並べ方」は計算が重く、リレーによって違ってよい。だから**リレーが並べて返す**。クライアントはそれを受け取って描くだけ。

## リクエスト

```
REQ "rec" [{"feed":"rec", "of":"<me>", "limit":20, "asof":1730700000, "offset":0}]
```

| 項目 | 意味 |
|---|---|
| `feed` | `"rec"` |
| `of` | 誰向けに並べるか(省略=個人化なし)。**認証済みの接続**が `of` と同じ pubkey のときだけ、非公開の情報(閲覧履歴)を使ってよい |
| `asof` | 順位の基準時刻。**この時刻のデータで順位を固定**し、ページを送っても並びがずれない。省略=現在。6時間より古い値は現在に置換 |
| `offset` `limit` | ページ送り |

## レスポンス

- ランク順に `EVENT`(kind 1、およびフォロー中の人の kind 2)。**このとき届く順番が意味を持つ**(`created_at` で並べ直さない)。
- `["EOSE", "rec", {"next": {"offset": 20, "asof": 1730700000}}]`。次ページは `next` をそのまま次の `REQ` に使う。`next` が無ければ終わり。
- 以降のライブ配信はしない(`EOSE` 後に `CLOSED` してよい)。

## 参考アルゴリズム(現行の `rec_rank` と定数)

リレー実装の自由だが、現行と同等にしたい場合:

1. **候補**: 直近14日(`REC_WINDOW`)のトップレベル投稿を新しい順に最大500件(`REC_POOL`)+ `of` がフォロー中の人のリポスト(時刻はリポスト時)。
2. **反応**: 人ごとに重みを合算 — いいね1.0・リアクション1.0・返信2.0・リポスト3.0・引用3.0。1人あたり上限4.0。自分の投稿への自分の反応は除く。
3. **基本点**: `(1 + 4·ln(1 + 反応合計)) × (経過時間h + 2)^-1.3`(`REC_GRAVITY`)。
4. **倍率**(個人化): フォロー中の作者 ×2.2 / 過去30日によく反応した作者 ×(1+min(0.8, 0.2·ln(1+回数))) / フォロー中の人が反応済み ×(1+min(1, 0.35·人数)) / **閲覧済み ×0.3**(kind 7 を使う) / 自分が反応・投稿した語に近い ×(1+min(0.6, …)) / 自分の投稿(30分以内)×4 / メディアあり ×1.08。
5. **揺らぎ**: ±8%(`asof` と投稿idで決まる固定値なので再現可能)。
6. **多様性**: 同じ作者の2本目以降を ×0.65ⁿ。
7. キャッシュ: `(of, asof)` ごとに1時間(`REC_CACHE_TTL`)。`of` なしは `asof` を1分単位に丸めて共有。

## 公開情報だけで動く

反応・リポスト・フォローは公開イベントなので、リレーは手元のデータだけで計算できる。閲覧済みの判定(kind 7)だけは認証つきの接続が必要。

## クライアントの扱い

- `feed` 非対応リレーなら「おすすめ」タブを隠す(`features` に `feed:rec`)。
- 自前で並べたい人は、全体タイムライン + `COUNT` で同じ計算をクライアントでも実装できる(拡張なしでも機能は再現可能)。

## 拡張ポイント

- `feed` の値を足す(`following` `popular` `local` …)だけで新しい並びを提供できる。クライアントは知らない値をリレーに渡さない。
