# 機能: 検索

- 使う: 拡張フィルタ `search` / `#t` / kind 1・10000
- 現行API: `search`(`#tag` ならタグ検索、それ以外はユーザー名・本文の部分一致)

## ハッシュタグ検索

`#語` で始まる入力は、**拡張なしの標準フィルタ**:

```
{"kinds":[1],"#t":["語(小文字)"],"limit":60}
```

## ユーザー検索

```
{"kinds":[10000],"search":"macaron","limit":10}
```
対象: プロフィールの `name` と `handle`([handle](handle.md))。入力先頭の `@` は取り除く。完全一致を先頭に並べるのはクライアントで行う。

## 投稿検索

```
{"kinds":[1],"search":"広島 カープ","limit":50}
```

## search の意味

- 値は文字列1つ。**解釈はリレーが決める**(現行は大文字小文字を区別しない部分一致 `LIKE '%…%'`)。日本語は単語境界がないので部分一致・N-gram が向く。
- 他のフィルタ項目と AND。結果の並びは `created_at` 降順(関連度順にしたいリレーは `feed` を使う)。
- `%` `_` `\` はエスケープして扱う(現行 `addcslashes`)。
- 非対応リレーは `search` を**無視する**ので全件が返る。クライアントは `features` に `search` があるか確認し、無ければ自前で絞り込むか、検索窓を隠す。

## ポリシー

重いのでレート制限を強めに(現行 30回/分)。`limit` の上限も低め。

## 拡張ポイント

- 演算子(`from:` `since:` `-除外`)はリレー独自拡張として `features` に宣言して足せる。
- 複数リレーに投げてマージするのはクライアントの自由([multi-relay](multi-relay.md))。
