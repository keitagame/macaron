# 機能: 閲覧者一覧・閲覧履歴

- 使う kind: [7](../kinds/7-view.md) / [30001](../kinds/30001-setting.md)(`no_view`) / [5](../kinds/5-deletion.md)
- 現行API: `view_seen` `noview` `thread`(`viewers`)

## 仕組み

- 投稿が画面に表示されたら(開かなくても)、クライアントが [kind 7](../kinds/7-view.md) を送る。自分の投稿・設定OFFのときは送らない。
- 投稿を開くと、その投稿の閲覧者一覧を見られる: `REQ {"kinds":[7],"#e":["<id>"],"limit":200}`(認証済みの接続だけ。投稿者本人は一覧から除く。現行は最大200人)。

## 送り方

```
POST /msg   [["EVENT",{kind:7,…}], ["EVENT",{kind:7,…}], …]   ← 最大50件(現行 view_seen と同じ)
```
画面に出た投稿を数秒ためてバッチで送る。短時間に多すぎるとリレーが `rate-limited:`(現行 60回/分)。

## 「閲覧を記録しない」

1. [kind 30001](../kinds/30001-setting.md) `d=no_view` を `"1"` にして保存(端末間で共有)。
2. 以降、kind 7 を送らない。
3. 過去分を消す: [kind 5](../kinds/5-deletion.md) の `["k","7"]`。

## 閲覧者一覧を見せる条件

- 見られる側(読み手)は**認証済みであること**(未ログインは見られない=現行と同じ)。
- 見せる範囲はリレーが決める: 「投稿者だけ」「認証済みの誰でも」など(現行は後者)。ポリシーとして `GET /` に出す。

## プライバシー

閲覧記録は個人の行動履歴なので、**既定の扱いはクライアントが決めて利用者に明示する**。リレー運営者には見える点も説明する。保持期間を `expiration` タグ(例: 30日)で限る運用を推奨。

## 利用

おすすめ順の「見たことがある投稿は下げる」に使われる([recommendation-feed](recommendation-feed.md))。
