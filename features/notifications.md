# 機能: 通知

- 使う kind: [1](../kinds/1-post.md) [2](../kinds/2-repost.md) [3](../kinds/3-reaction.md) [8](../kinds/8-follow.md)(**通知専用のイベントは無い**) / [30001](../kinds/30001-setting.md)(`notif_read`)
- 現行API: `notifs` `me`(`since` 付きポーリング)、`notify()` / `unnotify()`

## 考え方

通知は**自分宛て(`p` タグに自分がいる)のイベント**を購読したものにすぎない。リレーに通知テーブルも既読管理も無い。

## 購読

```
REQ "nt" [{"kinds":[1,2,3,8], "#p":["<me>"], "since": <最後に見た時刻>, "limit":50}]
```
`EOSE` 後は同じ購読で**リアルタイム**に届く(現行の20秒ポーリング+通知音/ポップアップの置き換え。[live-updates](live-updates.md))。

## 種類の判定(クライアント)

| 受け取ったイベント | 通知の種類(現行 `type`) |
|---|---|
| kind 1 に `q` タグ | `quote` |
| kind 1 に `e` タグ | `reply`(`p` に自分がいて、親の作者が自分) |
| kind 1 それ以外(`p` に自分) | `mention` |
| kind 2 | `repost` |
| kind 3 で `content == "+"` | `like` |
| kind 3 でそれ以外 | `react`(`content` が絵文字) |
| kind 8 | `follow` |

- **自分自身が作ったイベントは除外**(現行 `notify()` の `$to === $actor`)。
- 同じ種類・同じ相手・同じ投稿は1件にまとめる。
- 抜粋 = 対象投稿の本文先頭(一覧140字・ポップアップ80字)。本文が空でメディアのみなら「（画像・動画）」。
- 取り消された(削除された)いいね等は、購読を張り直せば自然に消える。ライブ中は [kind 5](../kinds/5-deletion.md) を受け取ったら該当通知を取り除く(現行の `unnotify` 相当)。

## 既読・未読数

- 既読位置 = [kind 30001](../kinds/30001-setting.md) `d=notif_read`(最後に通知画面を開いた時刻)。複数端末で共有される。
- 未読数 = `COUNT {kinds:[1,2,3,8],"#p":["<me>"],"since":<notif_read+1>}`(自分発の分は少し多く数える場合がある。厳密にしたいなら取得して数える)。
- 通知画面を開いたら `notif_read` を現在時刻に更新。

## DM

DM は通知に混ぜず、別バッジ: `{"kinds":[4],"#p":["<me>"],"since":<最後に会話を見た時刻>}`([kind 4](../kinds/4-direct-message.md))。

## ミュート・フィルタ

クライアント側で自由に(特定ユーザー・語)。プロトコルは関知しない。

## プッシュ通知(スマホ)

プロトコル外。リレーに「この pubkey 宛てのイベントが来たら Web Push する」登録APIを足す場合は、`/x/push` を [kind 20001](../kinds/20001-http-auth.md) 認証で作る(拡張)。
