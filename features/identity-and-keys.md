# 機能: 鍵・ログイン・サインアップ

- 使う kind: [10000 プロフィール](../kinds/10000-profile.md) / [20000](../kinds/20000-relay-auth.md) / [20001](../kinds/20001-http-auth.md)
- 現行API: `signup` `login` `logout` `me`

## 考え方

**アカウント = 鍵ペア。** メールもパスワードもセッションもリレー側には存在しない。「登録」は端末で鍵を作ること、「ログイン」は鍵を読み込むこと、「ログアウト」は鍵を端末から消すこと。

## サインアップ

1. クライアントが Ed25519 の鍵ペアを作る(秘密鍵 = 32バイト乱数)。
2. 表示名などを入れて [kind 10000](../kinds/10000-profile.md) を署名して送る。
3. (任意)ハンドルを取る([handle](handle.md))。

リレー側の「新規登録受付」(現行 `SIGNUP_OPEN`)は、`policy.signup` = `open` / `closed` / `invite` として表す。`closed` ならそのリレーは**新しいpubkeyの最初のイベント**を拒否する(`restricted: signups closed`)。

## ログイン

- **秘密鍵を入力** / **QR・ファイルから読み込み** / **署名拡張(下記)**。
- パスワードで鍵を守りたいなら、鍵を `scrypt` で派生した鍵で暗号化したファイル(`m1:` 形式、[encryption](encryption.md))を書き出し・読み込みできるようにする。**パスワードをリレーに送らない。**

## 鍵の保管(クライアント)

| 方法 | 安全性 | 備考 |
|---|---|---|
| 署名拡張・OS/ハードウェアの鍵 | 高 | 下記インターフェース |
| IndexedDB に暗号化して保存 | 中 | パスフレーズで復号。放置端末向け |
| WebCrypto の `extractable:false` の鍵 | 中 | 取り出せない=バックアップ不可。サブ鍵向け |
| localStorage に平文 | **低** | 非推奨(XSSで全部盗まれる) |

## 署名インターフェース(ブラウザ拡張・外部署名者)

```js
window.macaron = {
  getPublicKey():  Promise<hex>,
  signEvent(ev):   Promise<event>,                 // id と sig を付けて返す
  encrypt(pk, text): Promise<string>,              // "m1:…"
  decrypt(pk, text): Promise<string>,
};
```

アプリが秘密鍵を持たずに済む。現行のCSRFトークンのような防御は不要(署名要求は拡張が本人に確認する)。

## 鍵を失ったら

復旧できない(リレーに秘密はない)。バックアップを必ず促す。乗り換え用に「新しい鍵で kind 10000 に `["moved", "<旧pubkey>"]` を載せる」運用は可能だが、旧鍵の署名で `["moved_to", …]` を出せたときだけ信用する(約束事として別途追加)。

## パスワード変更・全端末ログアウト

存在しない概念。鍵を変える = 別アカウントへの引っ越し。
