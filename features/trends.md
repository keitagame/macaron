# 機能: トレンド

- 使う kind: [30002](../kinds/30002-trends.md)(リレー署名)
- 現行API: `trends`(`compute_trends()`、60秒キャッシュ、上位5件)

## 取得

```
REQ "trend" [{"kinds":[30002],"authors":["<リレーのpubkey>"],"#d":["main"]}]
```

1件返る。`content` を JSON として読み、押したら `q` を検索([search](search.md))へ渡す。以降は更新が購読で届く。

## 計算(リレー実装の参考。仕様ではない)

現行の `compute_trends`:

- 語の抽出: ハッシュタグ(`t`)+本文の一般語(漢字列・カタカナ列・英単語、ストップワード除外)。
- 「いま」= 直近 8時間。投稿時刻ごとに半減期 90分で重み付け。同じ人の連投は 0.4 ずつ減衰(1人が押し上げすぎない)。
- 「平常」= 過去7日間のユーザー×時間帯の出現頻度。
- 勢い = いまの重み ÷ 平常の期待値。上位 `TREND_LIMIT`(5)件に `label`(「トレンド」「急上昇」など)を付ける。
- 投稿が削除されたら除外、更新は60秒ごと(または投稿時に無効化)。

## 分散での注意

- リレーごとに見ている投稿が違うので、トレンドも**リレーごとに違う**。それが自然。
- クライアントが複数リレーのトレンドを合成してもよい。
- リレー運営者は不正な押し上げ(スパム)を除外してよい(自分の鍵で署名して出すので責任が明確)。

## 拡張ポイント

- `d` に地域・言語(`jp` `en`)を足す。
- `count` の他に `users`(関与ユーザー数)・`sample`(代表投稿id)を足す。
