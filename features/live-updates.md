# 機能: リアルタイム更新(ポーリングの置き換え)

- 使うもの: `REQ`(`EOSE` 後のライブ配信)/ [WebSocket](../core/06-transport-websocket.md) / [SSE](../core/07-transport-sse.md)
- 現行: `app.js` が `ntPoll`(20秒ごと)で `me?since=` を呼び、通知音・ポップアップ・未読バッジを更新

## 考え方

**購読を張りっぱなしにする。** 「新着があるか」を聞きに行かず、あれば届く。専用の「更新確認API」は不要になる。

## 張る購読

| 目的 | フィルタ | いつ |
|---|---|---|
| 通知(音・ポップアップ・バッジ) | `{"kinds":[1,2,3,8],"#p":["<me>"],"since":<now>}` | ログイン中ずっと |
| DM | `{"kinds":[4],"#p":["<me>"],"since":<now>}` | ログイン中ずっと |
| タイムラインの新着 | 表示中のタイムラインと同じフィルタ + `since:<最新>` | その画面を開いている間 |
| 設定の同期 | `{"kinds":[30001],"authors":["<me>"],"since":<now>}` | ずっと |

※ 認証が必要なもの(kind 4・7)は [20000](../kinds/20000-relay-auth.md)(WS)/ [20001](../kinds/20001-http-auth.md)(SSE の POST)。

## 接続戦略

1. WebSocket があれば WS。無ければ SSE。SSE も使えなければ **`POST /msg` で20〜30秒ごと**に `since` 付き `REQ`(現行と同等)。
2. 購読は**1接続にまとめる**(WS)。SSE は購読ごとに1接続なので、通知とDMは `POST /sse` で1本に束ねる(複数フィルタ)。
3. 切れたら再接続し、**最後に受け取った `created_at`(WS)または `Last-Event-ID`(SSE)から取りこぼしを埋める**。
4. タブが非表示のときは購読を減らす(通知だけ残す)。

## 画面の扱い

- 受け取ったイベントは検証(署名)してから反映。
- 新着投稿は自動で挿入しない: 「新しい投稿があります」を出してクリックで反映。
- 通知音・ポップアップは、**自分が操作した直後の自分宛て以外**(自分発は除外済み)に限り、初回の `EOSE` までは鳴らさない(過去分で鳴らさない)。

## 拡張ポイント

- 入力中表示・オンライン状態は ephemeral kind(2xxxx)で足せる。
